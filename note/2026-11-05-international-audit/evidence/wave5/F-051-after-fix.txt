## Bugs found and fixed
1. Wallet withdrawal accepted non-numeric amounts: amount "abc" or "NaN" set the balance to NaN (Postgres numeric stores NaN); 0.001, true, objects and arrays were also accepted. Now: positive, at most 2 decimals, within numeric(12,2); also enforced inside atomicWalletOp.
2. Switching a coupon on/off always failed with 500: the query set coupons.updated_at, which never existed. Migration 87 adds it.
3. Coupon validation answered 500 for a numeric code or a non-UUID seller_id, and a NaN or negative discount for a bad order_total; creation answered 500 for an unparseable expires_at. Now 400.
