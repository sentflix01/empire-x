Bugfix work implementing: **answer 503 AUTH_UNAVAILABLE when the user lookup fails (#203)**

## 2. Why does it exist?

requireAuth turned every error that was not TokenExpiredError into
401 INVALID_TOKEN, including Postgres failures such as "too many clients
already". The web app treats a 401 as an ended session, refreshes and can
sign the person out, so a short database outage signed people out.
- 401 only for token/account problems (any jwt.JsonWebTokenError,
  revoked token, user not found); 403 for banned accounts as before.
