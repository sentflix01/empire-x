## 2. Why does it exist?

The @/api/client interceptor rejects with the response body itself (plus
`status`), not an axios error, so every `err.response?.data?.error` read was
undefined and users only ever saw the generic fallback toast.
Add lib/apiErrorMessage.ts (`apiErrorBody`, `apiErrorMessage`) that handles
both the rejected body and raw axios errors, skips snake_case machine codes
in favour of the human `message`, and ignores network Error messages. Use it
