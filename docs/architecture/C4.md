## Level 4 — Code
*How does a specific module work internally?*

### Auth Module

```
POST /api/auth/login
        │
        ▼
routes/auth.ts
  ├── validate: email + password present
  ├── pool.query: SELECT user by email
  ├── bcrypt.compare(password, password_hash)
  ├── check is_verified = true
  ├── jwt.sign({ sub: user.id }, JWT_SECRET)
  └── return { access_token }
```

### Wallet Module

```
POST /api/wallet/topup
        │
        ▼
routes/wallet.ts
  ├── requireAuth (JWT verified)
  ├── validate: amount > 0
  ├── getOrCreateWallet(user.id)
  │     └── SELECT / INSERT wallets
  ├── UPDATE wallets SET balance = balance + $amount
  ├── INSERT wallet_transactions (type='credit')
  └── return updated wallet row

POST /api/wallet/debit  [admin only]
  ├── requireAuth + role === 'admin'
  ├── validate: user_id + amount > 0
  ├── getOrCreateWallet(user_id)
  ├── check balance >= amount
  ├── UPDATE wallets SET balance = balance - $amount
  ├── INSERT wallet_transactions (type='debit')
  └── return updated wallet row
```

### Feature Flag Module

```
isEnabled('personalized_feed', userId)
        │
        ├── check FF_PERSONALIZED_FEED env var
        │       └── if set → return true/false immediately
        │
        ├── check Redis: GET ff:personalized_feed
        │       └── if found → evaluateFlag(parsed, userId)
        │
        └── use DEFAULT_FLAGS['personalized_feed']
                └── evaluateFlag(flag, userId)
                      ├── if !enabled → false
                      ├── if rollout >= 100 → true
                      ├── if rollout <= 0 → false
                      └── hash(userId) % 100 < rollout → bool
```

## Frontend Component Architecture

```
app/
├── (auth)/              Public auth pages — no layout wrapper
│   ├── login/
│   ├── register/
│   ├── onboarding/
│   ├── forgot-password/
│   └── reset-password/
│
├── (app)/               Protected pages — wrapped in AppLayout
│   ├── layout.tsx       → AppLayout (sidebar, header, socket, auth check)
│   ├── page.tsx         → Home feed
│   ├── marketplace/
│   ├── products/[id]/
│   ├── messages/[id]/
│   ├── showrooms/[id]/
│   ├── profile/[id]/
│   └── ...              (20+ more pages)
│
└── p/[username]/        Public profile — server-rendered for SEO

Key provider nesting (providers.tsx):
ThemeProvider
  └── AuthProvider       (fetches /api/auth/me, sets user state)
        └── CartProvider (re-fetches cart after auth resolves)
              └── QueryClientProvider
                    └── App pages
```
